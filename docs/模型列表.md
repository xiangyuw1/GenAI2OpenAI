### 上下文长度测试说明

**测试方法**：使用大海捞针法（Needle in a Haystack），在文本中间（50%深度）插入关键信息，测试模型能否准确检索。

**历史测试结果**（部分模型已下线，且平台曾在同一 `aiType` 下更换底层模型，故结论未必仍然成立）：

- **deepseek-r1**: 100k tokens 通过，150k tokens 失败（返回空响应）——**已下线**
- **deepseek-v3**: 100k-200k tokens 全部通过——**已下线**
- **minimax-m1**: 100k-200k tokens 全部通过——**已下线**
- **chatglm**: 曾以 glm-5.1 测得 100k-200k 全部通过；当前底层已换为 GLM-5.3-Flash，需重测
- **qwen-instruct**: 曾以 qwen3.5-397b-a17b 测得 100k 即 HTTP 500；当前底层已换为 Qwen-3.8，需重测
- **GPT 系列**: 未测试。Azure OpenAI 模型有严格的额度限制，早期测试中所有请求返回空响应（`content: ""`），无法完成上下文长度测试。
- **Kimi-k3 / deepseek-pro / deepseek-chat**: 未测试

**注意**：

1. 实测上下文长度可能受上游服务稳定性影响
2. 平台会在不改 `aiType` 的前提下替换底层模型，历史实测数据需定期复核
3. 建议使用前先用小文本验证目标模型的实际表现
4. 当前部署的 access token 可能对 GPT 模型有额外限制
