### 上下文长度测试说明

**测试方法**：使用大海捞针法（Needle in a Haystack），在文本中间（50%深度）插入关键信息，测试模型能否准确检索。

**历史测试结果**（部分模型已下线，且平台曾在同一 `aiType` 下更换底层模型，故结论未必仍然成立）：

- **deepseek-r1**: 100k tokens 通过，150k tokens 失败（返回空响应）——**已下线**
- **deepseek-v3**: 100k-200k tokens 全部通过——**已下线**
- **minimax-m1**: 100k-200k tokens 全部通过——**已下线**
- **chatglm**: 曾以 glm-5.1 测得 100k-200k 全部通过；当前底层为 GLM-5.3-Flash，需重测
- **qwen-instruct**: 曾以 qwen3.5-397b-a17b 测得 100k 即 HTTP 500；当前底层为 Qwen-3.8，需重测
- **GPT 系列**: 未测试。Azure OpenAI 模型有严格的额度限制，早期测试中所有请求返回空响应（`content: ""`），无法完成上下文长度测试。
- **Kimi-k3 / deepseek-v4.1-flash / deepseek-chat**: 未测试

**注意**：

1. 实测上下文长度可能受上游服务稳定性影响
2. 平台会在不改 `aiType` 的前提下替换底层模型，历史实测数据需定期复核
3. 建议使用前先用小文本验证目标模型的实际表现
4. 当前部署的 access token 可能对 GPT 模型有额外限制

## 图片生成模型

| 请求 id（上游 aiType） | 实际 id                  | 建议命名                  | 可用性     |
| ---------------------- | ------------------------ | ------------------------- | ---------- |
| GPT-Image-2            | GPT-Image-2.5-Sunburst   | gpt-image-2.5-sunburst    | 已验证可用 |

图片模型通过图片生成端点调用（不是 `/v1/chat/completions`）：

- `POST /v1/images/generations`：文生图
- `POST /v1/images/edits`：带参考图生成/编辑（最多 4 张）

上游同一个 `/htk/chat/start/chat` 接口承载图片生成，必须携带 `size`、`quality`、`count`、
`style`、`outputFormat` 等图片参数；缺少这些参数时上游会报
`Invalid value: 'standard'`。图片结果 URL 形如 `image15test/xxxx.png`，需要拼接
`https://genaipic.shanghaitech.edu.cn/sys/common/static/` 才能访问，本项目会自动补全。

实测参数范围（2026-10-26）：

- `size`：`宽x高`，总像素需在 655360 ~ 8294400 之间；`1024x1024`、`1536x1024`、`2048x1152` 均可用
- `quality`：`low` / `medium` / `high` / `auto`
- `style`：`vivid` / `natural`
- `output_format`：`png` / `jpeg` / `webp`
- `n`：1 ~ 10（上游工作台默认 1）
- `background`：`auto` / `opaque` / `transparent`（可选；实测上游仍返回 `opaque`，透明背景暂不生效）

`gpt-image-1.5` 实测返回 `该模型无使用权限`，已列入下线模型。
